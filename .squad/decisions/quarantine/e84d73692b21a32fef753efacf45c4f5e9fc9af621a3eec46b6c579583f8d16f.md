# Stable #49 application policy rejection test contract

- **By:** Switch
- **When:** 2026-07-29T10:17:40+02:00
- **Context:** Tank is implementing GitHub issue #49 for production content-policy enforcement and custom Foundry RAI policy.
- **Decision proposed for tests:** Application-owned prompt-policy rejection should be distinguishable from provider safety rejection by a stable public code `content_policy_rejected` in the existing error envelope. Provider safety rejection should remain `safety_rejected` with the current safe generic provider message. Application-policy rejections should occur before `ImageGenerator.generate`, should not log raw title/description text, and should not be logged as provider dependency failures.
- **Why:** These assertions make #49's acceptance criteria falsifiable without live provider calls and prevent conflating application policy with provider safety controls.
