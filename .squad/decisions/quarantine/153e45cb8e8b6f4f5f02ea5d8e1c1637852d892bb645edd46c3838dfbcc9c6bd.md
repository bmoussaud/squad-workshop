**What:** Production resource-group topology: one rg-fantasy-cards-prod for all regional and global ARM resources (compute, storage, networking, monitoring); separate dedicated rg-fantasy-cards-shared for cross-environment shared infrastructure (Foundry, ACR, managed identities). Revisit per-region resource groups only when independent RBAC boundaries, regulatory isolation, or larger scale justifies the complexity.
**Why:** Project scope is small with single active region (France Central); one RG per environment minimizes governance and operational complexity and matches explicit user preference. Shared resources require separate lifecycle management, access control, and cost tracking outside environment resource groups. Revisit trigger conditions not yet met; growth to multi-region, independent regulatory requirements, or RBAC segmentation would prompt re-evaluation.
